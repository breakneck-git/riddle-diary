# Знаки управления Kindle — дизайн

## Зачем

Владелец (2026-11-28): «нужно сделать систему знаков, для управления. типа как треугольник который уже
есть, только для других функций, в том числе яркость, громкость И так далее». Неудобно сейчас: ради
подсветки и прочего приходится выходить из дневника в меню KOReader. Как строить — отдано оркестратору
(«делай»).

## Что есть на устройстве (ssh kindle, 2026-11-28, только чтение)

| возможность | факт | вывод |
|---|---|---|
| звук | `/proc/asound/cards`: «no soundcards»; в `/dev/snd` только `timer` | громкости нет — не делаем |
| подсветка | `/sys/class/backlight/max77696-bl`; `lipc com.lab126.powerd flIntensity` 0, `flMaxIntensity` 25; KOReader на PW2 — шкала 0..25 | ярче / тусклее — да |
| Bluetooth | `/sys/class/bluetooth` нет | нет |
| датчик поворота | `/sys/bus/iio/devices` нет | нет |
| кнопки | `max77696-onkey` (питание) + тач `cyttsp4_mt` | только перо/палец |
| Wi‑Fi | `com.lab126.cmd wirelessEnable` = 1 | вкл/выкл — да |

## Цели и границы

- Цель: владелец рисует на странице знак — дневник выполняет команду устройства и коротко печатает
  итог на месте страницы; чернила растворяются как обычно.
- Не цель: громкость (нет железа); меню со страницей кнопок; знаки, которые владелец рисует сам
  (образцы — вшитые); новые знаки для функций дневника (карта, печать — уже есть).
- Анти-цель: знак срабатывает на обычных буквах и рисунках (ложное срабатывание хуже пропуска);
  новый знак путается с треугольником, розой или ключом печати; команда без видимого итога.

## Подходы

- **А (выбран оркестратором).** Один распознаватель — `glyph.match` (тот же, что сверяет ключ печати)
  по вшитым шаблонам-штрихам знаков. Новый знак — строка в таблице шаблонов и команда, не новая
  эвристика. Пороги и шаблоны — по живым рисункам владельца из лога devmode, как у розы.
- Б (отклонён). Эвристика на каждый знак, как `triangle.lua` и `rose.lua`: на каждый знак свой модуль
  порогов и своя калибровка — копии одного решения.
- В (отклонён). Один знак открывает страницу печатных кнопок: надёжно, но владелец просил знак на
  функцию.

## Решено (оркестратор, владелец может поправить)

| знак | команда | итог на странице |
|---|---|---|
| стрелка вверх ↑ | подсветка ярче на шаг | «Подсветка N из 25» |
| стрелка вниз ↓ | подсветка тусклее на шаг, до выключения | «Подсветка N из 25» / «Подсветка выключена» |
| полумесяц | ночной режим (инверсия экрана) вкл/выкл | «Ночной режим включён/выключен» |
| квадрат | полное обновление экрана (снять «призраки») | — (видно само) |
| молния (зигзаг) | Wi‑Fi вкл/выкл | «Wi‑Fi выключен» / «Wi‑Fi включён» |

- Работают при любой печати — как треугольник: устройство, не данные дневника.
- Порядок проверок на странице: ключ печати → треугольник → знаки управления → роза → случайное
  касание → модель.
- Шаг подсветки — константа; выключенная подсветка + ↑ включает её на первый шаг.
- Под закрытой печатью с заданным ключом попытка, не ставшая знаком, файлом штрихов не пишется
  (как сейчас, `record`).

## Проверенные факты (spec-grounder 2026-11-28, ключевые перепроверены оркестратором)

| утверждение | источник |
|---|---|
| подсветка PW2 в KOReader — 0..25: `fl_max = 24`, у PW2 `canTurnFrontlightOff = no` → `fl_max + 1` | `frontend/device/kindle/powerd.lua:9,24`; `kindle/device.lua:909` |
| `setIntensity` сам ограничивает уровень | `frontend/device/generic/powerd.lua` `normalizeIntensity` |
| ночной режим — событие `ToggleNightMode` → `DeviceListener:onToggleNightMode`, перерисовка full, сохраняется `night_mode`; инверсия на Kindle аппаратная (`canHWInvert`) | `frontend/device/devicelistener.lua:14,22` |
| Wi‑Fi — `NetworkMgr:turnOnWifi/turnOffWifi` → `kindleEnableWifi`; ssh ходит по `wlan0` — выключение рвёт ssh | `kindle/device.lua` `initNetworkManager`; `ip -4 addr` |
| полное обновление — `UIManager:setDirty(..., "full")`; дневник рисует мимо UIManager (`Diary:push(..., "full")`) | `riddle_diarywidget.lua` |
| `glyph.match` сверяет только шаблон с тем же числом штрихов (как нарисовано или после склейки) → по шаблону на каждое число штрихов знака | `riddle/glyph.lua:194` |
| облако не зависит от направления и порядка штрихов, но не нормировано по повороту: ↑ и ↓ различаются положением головы | `glyph.lua` `canonical`, `cloud_of`; замер ↑/↓ 3.56 (2 штриха), 4.10 (1) |
| DIST = 3.0 подбирался по образцам владельца (свои пары до 3.47, чужие от 3.31) — для шаблонов знаков нужен свой порог | `glyph.lua` |
| на синтетике: одиночный крест (`fixtures.rose_strokes.cross_only`) совпадает со ↓ (2.84); стрелка в 1 штрих против зигзага — 3.14; треугольник и роза не срабатывают ни на одном шаблоне | замер luajit |

## ASSUMPTION — живой прогон

1. Аппаратная инверсия накрывает экран дневника (он рисует в `Screen.bb` мимо UIManager) и
   `ToggleNightMode` доходит до `DeviceListener`, пока дневник открыт.
2. Wi‑Fi включается знаком офлайн без всплывающего меню (`reconnectOrShowNetworkMenu`).
3. Расстояния — по живым рисункам владельца из лога devmode, не по синтетике.

## Оставлено строителю

Точные шаблоны и пороги (свой порог знаков, не DIST ключа), шаг подсветки, тексты итогов, матрица коллизий
в тестах: каждый знак против каждого, треугольника, розы, фикстур букв и чужих рисунков; обязательно
крест `cross_only` против ↓ и стрелка в 1 штрих против зигзага. Ключ печати владельца в матрицу не
входит (образец не читать); его порядок — первым — и так закрывает коллизию.
