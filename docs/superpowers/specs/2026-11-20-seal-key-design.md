# Печать дневника: графический ключ, правила в конфиге, данные под замком — дизайн

Задача Notion 40313e60-bc8d-811d-b72e-d60afdbba5aa: постановка владельца 2026-11-20 и его ответы на вопросы спеки
того же дня. План — `docs/superpowers/plans/2026-11-20-seal-key.md`. Пути кода — от `plugin/riddlediary.koplugin/`
(`R/` = `riddle/`), строки — по `3ccd3dc`.

## 1. Как это выглядело бы с самого начала

Печать — не «дверь в дневник», а **замок на данных пользователя**. Дневник (роль, ИИ) работает всегда. При закрытой
печати в запрос к модели не уходит ничего из данных пользователя, и модель об этом знает.

- **Открывает и закрывает** печать нарисованный знак — графический ключ. Kindle сравнивает его с образцом сам, без
  модели. Образец владелец задаёт в самом дневнике.
- **Когда печать закрывается**, задают правила в конфиге. По умолчанию печати нет.

Что из нынешнего уходит или меняется:

| Сейчас | Станет |
|---|---|
| Слово-печать читает модель (`read`), Kindle сравнивает нечётко: `R/seal.lua:177` `seal.matches`, `R/controller.lua:1020` `self.seal:feed(result.read)` | Убрать: слова нет. Ключ распознаётся по штрихам до модели (раздел 5) |
| Подсказки: `hint_every`, `hints` (`R/config.lua:135-148`), `Seal:feed` → `hint` (`R/controller.lua:1038`) | Убрать |
| `password_variants`, `seal_invalid` (`R/config.lua:150-156`, `R/controller.lua:73-74,85-93`) | Убрать; конфиг — таблица `seal` (раздел 3) |
| Закрытая печать = режим `locked`: модель видит только картинку и даёт уклончивый отказ (`R/controller.lua:874`, `R/prompt.lua:103-108,333-338`) | Убрать `locked`. Закрытая печать = обычный ответ в роли, контекст без данных (раздел 4) |
| `SEAL_OFF` «Печать снята…» при открытой печати (`R/prompt.lua:44,83-85,422-423`) | Заменить правилом закрытой печати: оно стоит в промпте только при закрытой |

Остаётся как есть:
- **Треугольник** открывает страницу состояния при любой печати (`riddle_diarywidget.lua:1370-1376`): на ней нет
  данных дневника.
- **Роза (карта)** открывается только при открытой печати (`riddle_diarywidget.lua:1378`): карта читает данные.
- **Синк Notion → Kindle** продолжается при любой печати (ответ владельца 5 — «а»). Данные доезжают на устройство, но
  не отдаются модели и не показываются.

## 3. Конфиг: правила печати

```lua
-- /mnt/us/riddle/config.lua
seal = {
  key = true,        -- по ключу: печать открывается и закрывается знаком; образец задаётся в дневнике (раздел 5)
  minutes = 30,      -- по времени: закрыть, если N минут не было записи
  on_sleep = true,   -- по блокировке Kindle: сон закрывает печать
  remember = true,   -- разговор при закрытой печати пишется в память дневника; по умолчанию true
  off = true,        -- флаг снятия: пока стоит, печати нет (знак забыт)
},
```

**Когда печать есть:**
- Нет таблицы `seal` или нет `key = true` и других правил — печати нет, данные доступны всегда. Это значение по
  умолчанию.
- Правила работают, только если у них есть значение. Открывает печать только `key`; `minutes` и `on_sleep` только
  закрывают.

**Флаг `off = true`:**
- Побеждает всё: печати нет, в лог пишется `riddle: seal off by flag`.
- Что при этом происходит с образцом ключа — раздел 8.

**Битый конфиг — печать закрыта**, в лог `riddle: seal config invalid: <причина>`:
- правило закрытия без `key`: закрыть можно, открыть нечем;
- `minutes` не целое ≥ 1;
- `key`, `on_sleep`, `remember` не булевы;
- файл конфига не загрузился.

Это сохраняет нынешнее «опечатка не открывает» (`R/config.lua:86`). Цена теперь низкая: ИИ отвечает и при закрытой
печати, а выход — флаг `off`.

**Остальное:**
- **Старт:** печать есть → она закрыта, как сейчас.
- **`remember`** не задан → `true` (ответ владельца 4).
- **Старые ключи** `password_variants`, `hint_every`, `hints` не читаются. Если есть `password_variants`, в лог один
  раз пишется `riddle: config password_variants ignored (seal is a drawn key now)`.
- **Сборка конфига Kindle** (`tools/push_config.sh`) пишет таблицу `seal` из файла `RIDDLE_SEAL`. Проверка через luajit
  переходит с `password_variants` на `seal` по правилам выше; отказ — ничего не записано, как сейчас
  (`tools/push_config.sh:167-180`). Образец ключа скрипт не трогает: его пишет дневник.
- **Риск при деплое:** на Kindle стоит слово, а таблицы `seal` нет → после деплоя печать исчезнет и данные откроются.
  До деплоя оркестратор пересобирает конфиг через `push_config.sh` с таблицей `seal`.

## 4. Данные пользователя: одна точка отсечения

### Какие пути читают данные

Всё, что уходит в модель как данные пользователя, собирает `Controller:_open_context(sid, parts)`
(`R/controller.lua:574-595`). Он вызывается в одном месте — `R/controller.lua:850`, перед `prompt.open`
(`R/controller.lua:861`).

| Данные | Чтение | В `_open_context` |
|---|---|---|
| Пересказы прошлых сессий | `Memory:summaries` (`R/memory.lua:311`) | `R/controller.lua:577` |
| Свёртка текущей сессии | `memory.rollup` | `R/controller.lua:583` |
| Последние реплики сессии | `Memory:recent` (`R/memory.lua:296`) | `R/controller.lua:589` |
| Лор (`lore.md`) | `Memory:lore_text` (`R/memory.lua:640`) | `R/controller.lua:586` |
| Знания из Notion (локальная SQLite, её пишет `R/sync.lua`) | `app.knowledge_text` (`R/app.lua:144`) через `Controller:_knowledge` (`R/controller.lua:164`) | `R/controller.lua:581,590` |
| Задачи Notion | `app.tasks_context` (`R/app.lua:188`) | `R/controller.lua:581,591-592` |

### Пути вне `_open_context`

- **Карта** (`map_read`) открывается розой только при открытой печати (`riddle_diarywidget.lua:1378`).
- **Импорт лора** `_sync_lore` (`R/controller.lua:1124`):
  - перед ответом — `R/controller.lua:847`, только без печати;
  - `Controller:_followup_lore` (`R/controller.lua:1263`) — из `on_unlocked_followup` (`R/controller.lua:1272`) и из
    `begin_followup` (`R/controller.lua:1285`).
- **Пересказ прошлой сессии** `_summary_job` (`R/controller.lua:1274,1289`) идёт в тех же хвостах. Он читает память и
  отправляет её модели. Хвост берётся после разблокировки или по `take_followup` (`R/controller.lua:1365-1386`).
- **Свёртка** (`prompt.roll`, `R/controller.lua:1173`) отправляет память модели для сжатия.
  - `roll_due` ставится после ответа с `job.answered` (`R/controller.lua:1068`).
  - Сейчас `job.answered` ставят только ответы `open` и `setup` (`R/controller.lua:1003,1016`).

### Решение

- **Один признак «данные доступны» = печать открыта** (или её нет).
  - Ветки `R/controller.lua:847,1376,1400` переходят с `self.sealed` на этот признак; поле `sealed` уходит.
  - Старт без печати и открытие ключом взводят пересказ и лор (`followup_due`).
- **`_open_context` при закрытой печати** возвращает контекст без данных: персона, правило закрытой печати
  (`ctx.seal = "closed"`) и реплики, сказанные при закрытой печати (ниже).
  - Сборщику промпта данные не передаются, поэтому утечь нечему; от модели ничего не требуется.
  - Режим ответа один — `open`. Ветка `locked` (`R/controller.lua:874`) и `prompt.locked` (`R/prompt.lua:333`)
    удаляются.
- **Хвосты при закрытой печати:**
  - не идут лор (`_followup_lore` и `:847`), пересказ прошлой сессии (`_summary_job` вида `session`) и свёртка —
    они ждут открытия;
  - идёт генерация персоны (`tail == "gen"`): она данных не читает.
- **Разговор при закрытой печати** (ответ владельца 4):
  - при `seal.remember` (по умолчанию `true`) реплики пишутся в память дневника обычным `_remember`
    (`R/controller.lua:135`); после открытия дневник их помнит;
  - при `false` — не пишутся;
  - в обоих случаях связность при закрытой печати даёт список реплик, сказанных с момента закрытия. Он живёт в памяти
    процесса, а не берётся из `Memory:recent`: тот вернул бы и реплики открытой печати, то есть данные. Список
    сбрасывают открытие печати и перезапуск.
- **Генерация персоны и «Чей это дневник?»** (`R/controller.lua:550,804-808`) данных пользователя не читают и при
  закрытой печати работают: условие — «данные нужны», а не «печать открыта».

## 5. Графический ключ

### Распознавание

**Что есть:**
- Два распознавателя фиксированных фигур: `R/triangle.lua:121` и `R/rose.lua:215`, оба `detect(strokes)`. Это чистые
  функции на общей геометрии `R/pen.lua`: `points`, `dist`, `length`, `joins`, `resample`, `turn`, `bend`
  (`R/pen.lua:6-85`).
- Вход — штрихи `{ p = { x1, y1, x2, y2, … } }`. Порядок и направление не важны (`R/triangle.lua:1-3`,
  `R/rose.lua:1-2`).
- Вызов — `Diary:isSign(mod, name, strokes)` (`riddle_diarywidget.lua:1793`). В devmode он пишет лог по критериям и
  файл штрихов в `/mnt/us/riddle/roses/` (`riddle_diarywidget.lua:1796,1811-1815`).
- Распознавателя «сравнить с заданным образцом» нет.

**Новый модуль `R/glyph.lua`.** Чистая функция `glyph.match(strokes, template) -> ok, dist`; `template` — список
рисунков образца.
- **Метод — облако точек, семейство $P:** штрихи склеиваются в одно облако, `pen.resample` → N точек, нормировка
  масштаба и центра, жадное сопоставление точек в обе стороны. `dist` — минимум по рисункам образца. Порядок и
  направление штрихов не важны.
- **Допуск `glyph.DIST`** подбирается по фикстурам до кода виджета:
  - совпадать должны 12 роз владельца между собой (`tests/fixtures/rose_owner.lua`) и треугольники между собой
    (`tests/fixtures/triangle_strokes.lua`) — одна фигура одной руки;
  - не совпадать — роза с треугольником и с буквами (`tests/fixtures/rose_strokes.lua`);
  - ложное открытие хуже пропуска (`R/triangle.lua:4`).
- **Лимиты:** `glyph.MAX_STROKES = 4` — страница со словами не сравнивается; `glyph.SIZE` — меньшая сторона рамки не
  меньше, чем у треугольника (`R/triangle.lua:21`, 150 px).

### Как задаётся ключ (ответ владельца 3 — «б»)

**Когда включается режим «задать ключ»:** в конфиге `key = true`, а образца `/mnt/us/riddle/seal_key.lua` нет. Печать
при этом закрыта: данных нет, ИИ отвечает.

**Шаги режима:**
1. Первая строка чистой страницы (`Controller:opening_text`) — «Нарисуй знак печати».
2. Страница с числом штрихов не больше `glyph.MAX_STROKES` — попытка знака: она не уходит в модель и не пишется в
   память. Страница со словами (больше штрихов) — обычный разговор при закрытой печати.
3. Первый рисунок проверяется: не треугольник, не роза (`triangle.detect`, `rose.detect` — иначе знак открывал бы
   страницу состояния или карту), не мельче `glyph.SIZE`. Не прошёл — фраза с причиной («этот знак занят» или «крупнее»),
   режим остаётся.
4. Прошёл — фраза «Ещё раз».
5. Второй рисунок сравнивается с первым (`glyph.match`). Совпал — оба рисунка пишутся образцом через
   `file.write_atomic` (`R/file.lua:18`), печать открывается, фраза «Знак запомнен».
6. Не совпал — «Не совпало, нарисуй знак заново», и режим начинается с шага 1.

**Поведение режима:**
- Повтор безопасен: до записи образца режим живёт только в памяти; перезапуск начинает его заново. Запись атомарна.
- Образец лежит на устройстве рядом с конфигом, как сейчас слово (`R/config.lua:10`); в git и в `push_config.sh` его
  нет.

### Открытие и закрытие

- **Порядок в `Diary:onPageDone`** (`riddle_diarywidget.lua:1370-1381`): ключ проверяется первым, затем треугольник,
  затем роза. Страница-ключ — не сообщение, как треугольник.
  - Закрытая печать — ключ открывает её с приветствием (`texts.welcomes` или `welcome` персоны).
  - Открытая — тот же ключ закрывает её фразой закрытия, ответ на экране стирается.
- **Промах** (страница до `glyph.MAX_STROKES` не совпала) — обычная страница, дальше по порядку.
- **devmode-запись попыток** в `roses/` идёт через тот же `isSign`. Proposal 41d13e60-bc8d-81a8 (писать штрих при
  закрытой печати только при распознанном знаке) решается здесь: при закрытой печати попытка ключа в файл не пишется.

## 6. Правила закрытия

- **`minutes`** (ответ владельца 2 — «б»): N минут от последней записи в дневнике.
  - Последняя запись — отвеченная страница или открытие ключом; время берётся из `deps.now`.
  - Проверка `seal:due(now)` стоит в начале `_begin`: просроченная печать закрывается до сборки контекста, поэтому
    данные не уходят даже без таймера.
  - Виджет после каждого ответа ставит `Diary:schedule(N минут)`. По срабатыванию печать закрывается, ответ на экране
    стирается и показывается первая строка.
  - После пробуждения (`Diary:onResume`, `riddle_diarywidget.lua:742`) — та же проверка: таймеры KOReader во сне не
    идут.
- **`on_sleep`** — `Controller:on_sleep` закрывает печать. `hold.survives_sleep` получает «сон закрывает печать»
  вместо «печать есть».

## 7. Роль при закрытой печати и счётчик попыток

### Как роль узнаёт, что печать закрыта

При `ctx.seal == "closed"` в промпт добавляется правило (заменяет `SEAL_OFF`, `R/prompt.lua:44`):

> Печать закрыта: памяти, знаний и задач того, кто пишет, у тебя сейчас нет. Если запись просит то, что требует их
> (что он писал раньше, его задачи, заметки, его вкусы и планы), скажи в своей роли, что для этого надо снять печать, и
> ответь тем, что можешь без них. Поставь "needs_data": true. Иначе "needs_data": false.

### Как определить «просьбу о данных»

- Вызова инструментов модели в дневнике нет: `grep -n "tools\b\|tool_choice\|function_call\|tool_calls" R/llm.lua`
  ничего не находит. Намерения приходят полями JSON-ответа — `task`, `map`, `picks` (`R/controller.lua:739-740,952,971-975`;
  `R/prompt.lua:147-164`).
- **Решение по их образцу:** просьбу распознаёт модель — ключ `needs_data`, только при закрытой печати.
  - Локальные ключевые слова отвергнуты: просьба о данных выражается свободно, список слов даёт и пропуски, и ложные
    срабатывания.
  - Модель данных не видит, поэтому ошибка флага стоит лишнего или пропущенного шага счётчика, а не утечки.

### Счётчик

- **Окно:** не меньше 5 просьб за 10 минут. Чистая функция над списком времён в памяти контроллера; пороги —
  константы.
  - Готового окна нет: `fails`/`hints_given` (`R/seal.lua:198-208`) считают без времени, `Memory:session`
    (`R/memory.lua:225`) — это окно сессии в 4 ч.
- **На 5-й просьбе** к ответу модели добавляется фиксированная фраза из `R/texts.lua` вне роли: «Чтобы открыть данные,
  нарисуй графический ключ». Окно начинается заново.
- **Сброс:** открытие печати и перезапуск.

## 9. Открытый вопрос владельцу

1. **Что флаг `off` делает с образцом ключа?** Флаг означает «знак забыт» (постановка), но новый знак как-то надо
   задать.
   - (а) **Рекомендую.** Пока стоит `off`, дневник удаляет образец. Флаг убран → режим «задать ключ» с нуля.
   - (б) Образец остаётся: `off` временно снимает печать, флаг убран — тот же ключ. Новый ключ задаётся отдельным
     полем `seal.reset_key = true`, которое удаляет образец при старте.
